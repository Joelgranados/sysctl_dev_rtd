==================
Self test re-write
==================

Target: `tools/testing/selftests/sysctl/sysctl.sh`
Written: 2026-08-14

This Doc was generated by AI

Goal
====

Restructure the sysctl selftests so that **adding a test means writing one
self-contained function** — no global variables to remember to initialize, no
positional metadata strings to edit, no chance that one test's failure
truncates the rest of the suite.

Decision: stay in bash
======================

Considered and rejected:

- **`kselftest_harness.h` (C)** — 176 in-tree users, forks a child per test
  (`kselftest_harness.h:435`) so state cannot leak, `FIXTURE_VARIANT` fits the
  per-target matrix well. Rejected because it drives the kernel through raw
  `write()`/`pwrite()`, which is *not* how `/proc/sys` is consumed in the wild.
- **pytest** — only two in-tree users (`selftests/hid/`, `selftests/drivers/sdsi/`),
  no shared kernel-wide harness. Needs external `pytest` + `pytest-tap`;
  `hid/run-hid-tools-tests.sh` skips its *entire* suite when they are missing,
  which would mean silent coverage loss on minimal CI images. Also does not
  actually solve the isolation problem — module-level Python state leaks between
  tests the same way shell globals do.
- **`kselftest/ksft.py`** — stdlib-only KTAP helpers (users: `damon`,
  `x86/bugs`, `devices/probe`). Viable middle ground, but thin (no fixtures, no
  discovery, no parametrize) and buys nothing over bash here.

**Rationale for bash:** admins and config-management tools reach `/proc/sys`
through `echo >`, `sysctl -w`, `tee`, and `dd`. Those produce exactly the write
patterns (single write, byte-at-a-time short writes, seeks, over-long writes)
that the proc_handlers must get right. Testing through the shell tests the real
consumer rather than a proxy for it. The problem with the current script is not
the language — it is that it predates the conventions the tree has since settled
on.

Infrastructure to build on
==========================

`ktap_print_msg`, `ktap_exit_fail_msg`, `ktap_finished`, and the constants

Roughly 20 in-tree users (`cpufreq/main.sh`, `dt/test_unprobed_devices.sh`,
`exec/check-exec-tests.sh`, `power_supply/`, `rdma/`, `kho/vmtest.sh`,
`net/ovpn/common.sh`, `net/packetdrill/ksft_runner.sh`, …).

**Important:** `tools/testing/selftests/Makefile:279` installs it
unconditionally into `$(INSTALL_PATH)/kselftest/`:

    install -m 744 kselftest/ktap_helpers.sh $(INSTALL_PATH)/kselftest/

so `source "${DIR}"/../kselftest/ktap_helpers.sh` works from an installed tree
with **no** `TEST_FILES` change needed in `selftests/sysctl/Makefile`.

**`tools/testing/selftests/net/lib.sh`** — the runner discipline to copy

- `RET` is per-test and **the runner clears it**, not the test (`net/lib.sh:29`,
  `tests_run()` at `:443`)
- `check_err` / `check_fail` (`:456`, `:470`) *accumulate* into `RET` instead of
  exiting
- `log_test` (`:403`) emits one result line, merges into `EXIT_STATUS`, and
  **returns** — a failing test never truncates the suite

Design
======

Three structural properties, each fixing one class of hazard:

1. **Runner owns `RET`.** `RET=$KSFT_PASS` is set by `run_one()` inside the
   subshell before dispatch, so an uninitialized-global hazard is
   unrepresentable — a test author cannot forget it.
2. **Assertions accumulate, never `exit`.** Every sub-check in a test reports,
   even when an earlier one fails. No early bail-out hiding later results.
3. **Subshell per test.** A test cannot leak variables, cwd, or traps into the
   next one, and a stray `exit` inside a test kills only its own subshell. This
   is the bash analogue of the fork-per-test isolation in
   `kselftest_harness.h`.

Plus: **auto-discovery.** `declare -F | grep '^test_'` finds tests, so adding
one is a single function. This deletes the whole
`ALL_TESTS="0013:1:1:int_0003:1"` scheme along with `get_test_count`,
`get_test_enabled`, `get_test_target`, `get_test_skip_no_target`,
`remove_leading_zeros`, and the `awk -F":"` positional-field parsing.

Skip-if-target-missing moves *into* the test (`[[ -f "$t" ]] || RET=$KSFT_SKIP`)
instead of being a positional `SKIP_NO_TARGET` flag in a metadata string.

CLI: replace `-t/-w/-c/-s <4-digit-id>` with `TESTS='test_foo test_bar'`
env-var filtering (net/lib.sh convention) plus a `-r N` repeat flag.

Skeleton
========

```bash
#!/bin/bash
# SPDX-License-Identifier: GPL-2.0-or-later OR copyleft-next-0.3.1
DIR="$(dirname "$(readlink -f "$0")")"
source "${DIR}/../kselftest/ktap_helpers.sh"

SYSCTL=${SYSCTL:-/proc/sys/debug/test_sysctl}
readonly INT_MAX=$(((1 << 31) - 1))

# ---- assertions: emit a KTAP diagnostic, return non-zero, never exit --------

assert_write_rejected()   # <file> <value>
{
	local file=$1 val=$2
	if printf '%s' "$val" > "$file" 2>/dev/null; then
		ktap_print_msg "$file: write of '$val' succeeded, expected rejection"
		return 1
	fi
}

assert_content()          # <file> <expected>
{
	local file=$1 want=$2 got
	got=$(cat "$file")
	[[ "$got" == "$want" ]] && return 0
	ktap_print_msg "$file: got '$got', want '$want'"
	return 1
}

# ---- tests: one function, prefix test_, entirely self-contained ------------

test_int_array_no_partial_update()
{
	local t="${SYSCTL}/int_0003"

	[[ -f "$t" ]] || { RET=$KSFT_SKIP; return; }
	printf '%s' "1 2 3 4" > "$t" || { RET=$KSFT_FAIL; return; }

	# bad 3rd element (not a number)
	assert_write_rejected "$t" "10 20 abc 40"              || RET=$KSFT_FAIL
	assert_content        "$t" "1 2 3 4"                   || RET=$KSFT_FAIL

	# bad 3rd element (overflows int)
	assert_write_rejected "$t" "10 20 $((INT_MAX + 1)) 40" || RET=$KSFT_FAIL
	assert_content        "$t" "1 2 3 4"                   || RET=$KSFT_FAIL

	# bad 1st element
	assert_write_rejected "$t" "abc 20 30 40"              || RET=$KSFT_FAIL
	assert_content        "$t" "1 2 3 4"                   || RET=$KSFT_FAIL
}

# ---- runner ---------------------------------------------------------------

run_one()
{
	local name=$1

	# Subshell: a test cannot leak vars/cwd/traps into the next one, and an
	# accidental `exit` inside a test kills only its own subshell.
	( RET=$KSFT_PASS; "$name"; exit $RET )

	case $? in
	$KSFT_PASS) ktap_test_pass "$name" ;;
	$KSFT_SKIP) ktap_test_skip "$name" ;;
	*)          ktap_test_fail "$name" ;;
	esac
}

ALL_TESTS=$(declare -F | awk '{print $3}' | grep '^test_' | sort)

ktap_print_header
ktap_set_plan "$(wc -w <<< "${TESTS:-$ALL_TESTS}")"
for t in ${TESTS:-$ALL_TESTS}; do run_one "$t"; done
ktap_finished
```

Keep the shell-flavoured write patterns
=======================================

The `dd`-driven cases are the *reason* to stay in bash. Preserve them as named
helpers rather than inline one-liners:

- `write_in_chunks <file> <str> <bs>`   — replaces `dd if=... of=... bs=1`
- `write_at_offset <file> <str> <seek>` — replaces `dd ... bs=1 seek=1 skip=1`
- `write_overlong <file> <pad> <str>`   — replaces
  `(perl -e 'print "A" x 50;'; echo "$TEST_STR") | dd of="$TARGET" bs=50`

Test 0006's 50 repetitions become a runner `-r 50` flag, not a per-test
metadata field.

Known limits of the bash approach
=================================

- Cannot observe `errno`. `printf > file` collapses `EINVAL`, `ERANGE`, and a
  short write into exit status 1; `dd` only reports block counts. If a future
  test needs to distinguish them, add a small C helper for *that* test only —
  a hybrid is fine and does not argue against bash for the rest.
- `dmesg` scraping (0012) stays inherently racy; keep it isolated in one test.

Makefile impact
===============

`tools/testing/selftests/sysctl/Makefile` currently has only
`TEST_PROGS := sysctl.sh` plus `include ../lib.mk`. **No change required** —
`ktap_helpers.sh` is installed by the top-level selftests Makefile, and nothing
new is sourced from within `selftests/sysctl/`. If any helper is later split
into a local file (e.g. `sysctl_lib.sh`), it MUST be added to `TEST_FILES` or
the test will fail after `make install` while still passing in-tree.
